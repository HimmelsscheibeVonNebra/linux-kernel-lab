7주차 첫 번째 수업은 실행 중인 프로세스 하나를 놓고 세 가지를 관찰합니다. 주소 공간(코드·데이터·힙·스택이 어디에 놓이는가), 상태(지금 무엇을 하고 있는가), 자원(무엇을 열고 있고 얼마나 쓰며 어디까지 쓸 수 있는가)입니다. 수업 내내 같은 동작을 반복합니다. 프로그램이 스스로 보고한 값을 ps와 /proc/PID가 밖에서 보여 주는 값과 맞춰 보는 것입니다. 본문에 나오는 주소와 숫자는 Ubuntu 24.04(x86-64, 커널 6.8) 실습 서버에서 실제로 관찰한 값입니다.

프로그램과 프로세스

프로그램은 파일, 프로세스는 실행 중인 묶음

프로그램은 파일입니다. /usr/bin/sleep은 디스크에 있는 기계어와 초기 데이터일 뿐입니다. 프로세스는 그 파일을 실행 중인 상태와 자원의 묶음입니다. 같은 /usr/bin/sleep을 sleep 30과 sleep 60으로 두 번 실행하면 PID가 다른 프로세스 두 개가 생기고, 각 프로세스는 자기만의 주소 공간(코드·데이터·힙·스택), 상태(예: 잠자기 S), FD 표(0·1·2가 터미널을 가리킴), 자원 사용량(CPU 시간·메모리)을 따로 가집니다. 같은 프로그램이어도 PID·상태·자원은 프로세스마다 따로 있다는 점이 출발점입니다.

커널은 프로세스마다 기록을 하나씩 유지합니다. Linux에서는 task_struct라는 커널 구조체가 이 기록을 담고, /proc/PID 디렉터리가 그 기록을 밖에서 들여다보는 창 역할을 합니다. 기록의 항목과 그것을 보는 창은 다음과 같습니다.

1부 · 주소 공간

코드·데이터·힙·스택이 실제로 어느 주소에 놓이는지를 /proc/PID/maps로 확인합니다.

가상 주소 공간의 배치

프로세스의 가상 주소 공간은 낮은 주소에서 높은 주소 쪽으로 다음 순서로 배치됩니다. 괄호 안은 addr_show를 한 번 실행했을 때 관찰한 시작 주소입니다.

  1. 코드 · 읽기 전용 데이터 (0x5d1753c53000)
  2. 데이터 · BSS (0x5d1753c57000)
  3. 힙 [heap] — 높은 주소 쪽으로 자랍니다 (0x5d1757702000)
  4. (비어 있음)
  5. 공유 라이브러리 · mmap (0x7725d1c00000)
  6. (비어 있음)
  7. 스택 [stack] — 낮은 주소 쪽으로 자랍니다 (0x7ffe168ff000)
  8. 커널 영역 — 사용자 프로그램은 접근할 수 없습니다

이 배치에서 세 가지를 읽어 낼 수 있습니다.

  • 구역마다 규칙이 다릅니다. 코드는 읽고 실행할 수 있고, 데이터는 쓸 수 있습니다. 힙은 malloc이, 스택은 함수 호출이 키웁니다.
  • 빈 공간이 대부분입니다. 주소 공간은 넓고 거의 비어 있으며, 매핑된 곳만 쓸 수 있습니다.
  • 실행마다 달라집니다. ASLR이 각 구역의 시작 위치를 섞기 때문에, 같은 프로그램도 실행할 때마다 주소 값이 바뀝니다. 구역의 순서는 같고 값만 매번 다릅니다.

변수 선언이 구역을 정한다

변수가 어느 구역에 놓이는지는 선언 방식, 정확히는 저장 기간(storage duration)이 정합니다. 정적 저장 기간을 가진 것은 데이터·BSS에, 자동 저장 기간은 스택에, 동적 저장 기간은 힙에 놓입니다.

선언성격놓이는 구역
int global_init = 7;전역 · 초기값 있음데이터 (.data)
int global_zero;전역 · 초기값 없음BSS (.bss) · 0으로 시작
static int local_static = 9;함수 안이어도 static데이터 (.data)
int local = 3;함수 안의 지역 변수스택 · 함수 프레임
char *heap1 = malloc(64);heap1이 가리키는 블록힙 · free까지 유지
int main(void) { ... }함수의 기계어코드 (.text) · 읽기·실행

가상 주소와 물리 메모리

프로그램이 보는 주소는 가상 주소이고, 프로세스마다 자기 주소 공간을 가집니다. 커널은 프로세스별 페이지 표에 4 KiB 페이지 단위로 "이 가상 페이지는 어느 물리 프레임에 대응하는가"를 기록합니다.

이 구조에서 격리와 공유가 함께 나옵니다. 프로세스 A와 B의 스택이 같은 가상 주소대(0x7ffe…)에 있어도 서로 다른 물리 프레임에 대응하므로 서로의 값을 건드리지 못합니다. 반대로 libc 코드처럼 읽기 전용인 내용은 두 프로세스가 한 프레임을 함께 쓸 수 있습니다. %p로 출력한 주소는 모두 가상 주소이고, 물리 주소는 사용자 프로그램이 볼 수 없습니다.

addr_show: 구역별 주소 출력

addr_show는 구역이 다른 변수들을 한 프로그램 안에 만들어 놓고 그 주소를 출력합니다.

int global_init = 7;         /* 데이터 */
int global_zero;             /* BSS */
int local = 3;               /* 스택 */
static int local_static = 9; /* 데이터 */
char *heap1 = malloc(64);    /* 힙 */
printf("data=%p bss=%p\n",
       (void *)&global_init, (void *)&global_zero);
printf("data_static=%p stack=%p\n",
       (void *)&local_static, (void *)&local);
printf("heap1=%p heap2=%p\n",
       (void *)heap1, (void *)heap2);
  • %p와 (void *): 포인터 출력 서식 %p는 void *를 받으므로 변환해서 넘깁니다.
  • 관찰 시간: [seconds] 인자만큼 프로세스가 살아 있어, 그동안 같은 PID의 maps를 읽을 수 있습니다.
  • 비교하지 않는 것: 서로 다른 객체의 주소를 크고 작다로 비교하는 것은 C에서 정의되지 않습니다. 그래서 프로그램 안에서 주소끼리 대소 비교를 하지 않고, 출력한 값을 maps와 대조합니다.

실행 결과의 주소는 세 무리로 나뉩니다. 0x5d1753c57…로 시작하는 데이터·BSS, 0x5d175770…로 시작하는 힙, 0x7ffe…로 시작하는 스택입니다. 힙 블록 두 개의 주소 차이 heap2 − heap1은 0x50, 즉 80입니다. 요청한 64바이트에 할당자의 관리 정보가 더해진 간격입니다. 또 포인터 변수 heap1 자체의 주소(&heap1)는 0x7ffe…로 시작합니다. 변수는 스택에 있고, 그 변수가 가리키는 블록만 힙에 있다는 뜻입니다.

addr_show의 maps 전체

addr_show 프로세스의 maps 전체는 23행이었고, 위에서부터 다음 묶음으로 읽을 수 있습니다.

  • 1–5행 · 실행 파일: 헤더, 코드(r-xp), 상수, RELRO, 데이터(rw-p)의 다섯 갈래입니다.
  • 6행 · [heap]: brk로 늘리는 힙입니다. 크기는 0x21000 = 132 KiB입니다.
  • 7–11행 · libc: 실행 파일과 같은 다섯 갈래 구성입니다.
  • 12–14행 · 이름 없는 rw-p: 라이브러리의 BSS, 스레드 지역 저장소 등입니다.
  • 15–19행 · 동적 링커 ld.so: 실행 직후 라이브러리를 적재하는 프로그램입니다.
  • 20행 · [stack]: 주 스레드의 스택입니다. 크기는 0x21000 = 132 KiB입니다.
  • 21–23행 · vvar 등: 커널이 넣어 준 빠른 호출 영역(vdso)과 옛 호환 영역(vsyscall)입니다.

출력한 주소를 maps 구역에 넣기

권한 문자로 구역 알아보기

  • r-xp — 코드: 읽고 실행할 수 있고 쓸 수 없습니다. 코드에 쓰려고 하면 프로세스는 SIGSEGV로 끝납니다.
  • r--p — 읽기 전용 데이터: 문자열 상수와, 재배치가 끝난 주소 표(RELRO)가 여기에 놓입니다.
  • rw-p — 데이터·힙·스택: 쓸 수 있는 구역입니다. p는 쓰기가 이 프로세스의 사본에만 반영된다는 뜻입니다.

---p처럼 권한이 하나도 없는 행은 경계용 보호 구역입니다.

힙과 스택의 수명

스택과 힙은 크기를 바꾸는 주체가 다릅니다. 스택은 함수 호출이, 힙은 malloc·free가 바꿉니다.

  • 스택: 자동 수명. 스택 프레임은 호출 순서대로 쌓여, 호출되면 생기고 반환하면 사라집니다. main이 parse를, parse가 helper를 불렀다면 helper의 지역 변수 int local은 helper의 프레임 안에 있고, helper가 반환한 뒤 그 주소는 무효입니다. 그래서 지역 변수의 주소를 돌려주면 안 됩니다.
  • 힙: 명시적 수명. 힙 블록은 malloc으로 생기고 free로 사라지며, 함수 경계와 무관합니다. helper가 malloc한 블록은 helper가 끝나도 남습니다. free를 잊거나 포인터를 잃으면 누수가 되고, 두 번 free하면 정의되지 않은 동작입니다. free된 자리는 재사용될 수 있습니다.
  • 크기 한계. 스택은 RLIMIT_STACK(보통 8 MiB)까지만 자랄 수 있습니다. 깊은 재귀는 이 한계에서 죽습니다.

예약한 크기와 올라와 있는 크기

/proc/PID/status에는 메모리 숫자가 여러 개 나오는데, 가장 먼저 구별해야 할 것은 두 가지입니다.

  • VmSize (VSZ): 매핑한 가상 주소 범위의 합입니다. 예약일 뿐이고 메모리 사용이 아닙니다.
  • VmRSS (RSS): 지금 물리 메모리에 올라와 있는 페이지의 합입니다. 공유 페이지도 포함합니다.

둘이 다른 이유는 요구 페이징입니다. 페이지는 프로세스가 처음 건드릴 때 물리 메모리에 올라오므로, 매핑은 했지만 아직 건드리지 않은 부분은 VmSize에만 잡힙니다. 그래서 VmRSS ≤ VmSize입니다.

state_show를 실행하는 동안 읽은 실제 값은 VmSize 2684 kB, VmRSS 1800 kB였고, 구역별로는 VmExe(실행 파일 코드) 4 kB, VmData(데이터·힙) 224 kB, VmStk(스택) 132 kB, VmLib(공유 라이브러리) 1752 kB였습니다. 작은 C 프로그램도 VmLib, 즉 libc가 대부분을 차지합니다. libc 페이지는 다른 프로세스와 공유되므로, 프로세스들의 RSS를 그냥 더하면 시스템 전체 사용량보다 커집니다. 이 숫자들을 직접 측정하는 실험은 7주차 2차시의 pagetouch에서 합니다.

maps_show: /proc/self/maps 세기

maps_show는 자기 자신의 maps를 읽어 구역을 분류하고 셉니다.

FILE *fp = fopen("/proc/self/maps", "r");
while ((len = getline(&line, &cap, fp)) != -1) {
    total++;
    if (strstr(line, "[heap]") != NULL) ...       /* 행 출력, heap++ */
    else if (strstr(line, "[stack]") != NULL) ... /* 행 출력, stack++ */
    else if (strstr(line, ".so") != NULL) so++;
}
  • self: /proc/self는 읽는 프로세스 자신을 가리키는 링크입니다. PID를 몰라도 자기 정보를 읽을 수 있습니다.
  • getline: 길이 제한 없이 한 행씩 읽고, 버퍼는 마지막에 한 번 free합니다.
  • so_regions=10: 이 값은 libc 5행 + ld.so 5행을 센 것입니다. 라이브러리 개수(2개)가 아니라 .so가 들어 있는 매핑 행의 수입니다.

  • [static 함수] 이 파일 안에서만 보이는 함수

원칙은 변수에 대해 "어디서 보이나(범위)"와 "언제까지 사나(수명)"를 따로 묻는 것입니다. 포인터 변수와 그것이 가리키는 대상도 따로 셉니다. 변수를 가르는 축은 셋입니다. 범위(scope)는 이름이 어디서 보이는가, 저장 기간은 언제까지 사는가, 연결은 다른 파일에서도 같은 것인가입니다.

함수 밖에서 선언함수 안에서 선언
static 없음[전역] 파일 범위 · 정적 수명(데이터·BSS) · 다른 파일에서도 보임[지역] 블록 범위 · 자동 수명(스택 프레임)
static 있음전역이되 이 파일 안에서만 보임(내부 연결)[static 지역] 블록 범위 · 정적 수명(데이터·BSS)

static이라는 낱말은 놓인 자리에 따라 뜻이 다릅니다. 함수나 전역 변수 앞의 static은 "이 파일 안에서만 보인다"는 뜻이고, 함수 안 변수의 static은 "수명이 전역과 같다"는 뜻입니다. 가장 헷갈리기 쉬운 것이 static 지역입니다. 선언 위치는 함수 안이라 범위는 블록이지만, 수명과 놓이는 구역은 전역과 같습니다. 세 축을 섞지 않는 것이 핵심입니다.

빠른 규칙 여섯 가지

  • 괄호 안 매개변수는 지역 변수입니다. 호출할 때 값이 복사됩니다. 포인터 매개변수는 호출자의 변수를 가리킬 수 있습니다.
  • for·if·while·else의 중괄호 안에서 선언한 변수는 그 블록이 끝나면 사라집니다. 다른 블록에서 같은 이름을 다시 쓸 수 있습니다.
  • 포인터 변수와 가리키는 대상은 따로 셉니다. 변수는 스택, malloc 블록은 힙, 문자열 리터럴은 읽기 전용 데이터에 있습니다.
  • 배열 지역 변수(char line[256], int fds[1024])는 그 크기만큼 통째로 스택에 있습니다.
  • errno는 헤더가 제공하는 특별한 이름입니다. 전역처럼 쓰지만 스레드마다 하나입니다.
  • fork 뒤에는 같은 지역 변수가 두 프로세스에 각각 존재하며 값이 다를 수 있습니다(2차시 reap_show의 child).

addr_show.c

addr_show는 저장 기간이 구역을 정한다는 것을 보여 주려고 만든 예제입니다. 전역 둘, static 지역 하나, 지역 여럿, 힙 블록 둘을 한 함수에서 만들고 주소를 출력합니다.

  • 파일 주석과 전역 둘. 파일 머리의 주석은 함수 주소를 void *로 변환하는 일과 별개 객체의 포인터 대소 비교를 하지 않는다고 미리 밝힙니다. 둘 다 C가 정의하지 않기 때문이며, 코드 영역은 maps의 실행 권한(x)으로 찾습니다. global_init은 함수 밖 선언이라 파일 범위이고, 초기값이 있어 데이터 구역에 놓이며 프로그램이 끝날 때까지 삽니다. global_zero는 초기값이 없어 BSS에 놓이고 시작 때 0입니다.
  • 인자 검사. argc·argv는 호출할 때 값이 복사되는 main의 지역 변수로 스택 프레임에 있습니다. 초 인자는 strtol로 해석하는데, end는 if 블록 안에서만 보이는 지역 변수로 strtol이 숫자가 끝난 자리를 적어 줍니다. 숫자가 없거나(end == argv[1]), 글자가 남았거나(*end), 0–600 범위를 벗어나면 사용법을 표준 오류로 출력하고 종료 상태 2로 끝납니다.
  • 범위와 수명은 다른 축. static int local_static = 9;는 main 안에서 선언해 main에서만 보이지만, static 때문에 수명은 전역과 같고 데이터 구역에 놓입니다. 초기화 = 9는 프로그램 시작 때 한 번만 일어납니다. 같은 함수 안에서 선언한 local(출력의 stack=)과 구역이 다르다는 것이 출력으로 확인됩니다.
  • 변수와 가리키는 대상. 포인터 변수 heap1·heap2는 스택에 있고, 각각이 가리키는 64바이트 블록은 힙에 있습니다. 다음 두 줄의 차이가 곧 "변수"와 "가리키는 대상"의 차이입니다. 
    printf("pointer_on_stack=%p\n", (void *)&heap1);
printf("heap1=%p heap2=%p\n", (void *)heap1, (void *)heap2);
  • malloc 실패 처리. 둘 중 하나라도 NULL이면 둘 다 free하고 종료 상태 1로 끝납니다. free(NULL)은 아무 일도 하지 않으므로 안전합니다.
  • 대기와 해제. 출력을 flush한 뒤(실패하면 두 블록을 free하고 종료 1) 지정한 초만큼 기다립니다. sleep은 시그널로 깨면 남은 초를 돌려주므로 0이 될 때까지 반복합니다. 
    unsigned int remaining = (unsigned int)seconds;
while (remaining != 0)
    remaining = sleep(remaining);
    마지막에 두 블록을 free합니다. 지역 변수는 return과 함께 저절로 사라지지만 힙 블록은 free해야 사라집니다.

maps_show.c

maps_show는 /proc/self/maps를 한 행씩 읽어 분류합니다. 전역 변수가 없고, 힙은 getline이 잡는 버퍼 하나뿐입니다.

  • fp. FILE 객체 자체는 라이브러리가 힙에 만들고, fp는 그 주소를 담는 스택 변수입니다.
  • 이식성 분기. /proc/self/maps를 열지 못했을 때 Linux라면 실제 오류를 perror로 보고하고 종료 1, 다른 시스템이라면 maps=unsupported (no /proc on this system)을 출력하고 종료 0입니다. #ifdef __linux__로 갈라 둡니다.
  • line과 버퍼. line은 NULL로 시작하는 포인터입니다. getline이 힙에 버퍼를 잡고 그 주소를 line에 써 주며, 버퍼를 늘릴 때마다 cap을 갱신합니다. 변수는 스택, 버퍼는 힙입니다. len은 읽은 길이 또는 -1입니다.
  • 카운터 넷. long total = 0, heap = 0, stack = 0, so = 0;처럼 한 줄에 선언해도 각각 별개의 지역 변수입니다.
  • 오류 확인과 정리. getline의 -1은 파일 끝일 수도 오류일 수도 있으므로 ferror(fp)로 확인하고, 오류였으면 free·fclose 뒤 종료 1입니다. 힙 버퍼를 돌려주는 것은 지역 변수 line이 사라지는 일이 아니라 free(line) 호출입니다. 요약 한 줄을 출력한 뒤 fclose와 fflush의 결과도 검사하고 종료 0으로 끝납니다.

상태 전이 지도

상태 사이의 이동은 다음과 같습니다.

  • 실행 대기(R) → 실행 중(R): CPU를 받습니다.
  • 실행 중(R) → 실행 대기(R): 시간 조각이 끝나거나 스스로 양보합니다.
  • 실행 중(R) → 사건 대기(S·D): read, sleep 등으로 기다리기 시작합니다.
  • 사건 대기(S·D) → 실행 대기(R): 사건이 도착해 깨어납니다.
  • → 멈춤(T): Ctrl+Z나 SIGSTOP. 멈춤에서는 fg·bg·SIGCONT로 돌아옵니다.
  • 실행 중(R) → 좀비(Z): exit 등으로 종료합니다.
  • 좀비(Z) → 사라짐: 부모가 wait하면 프로세스 표에서 삭제됩니다.

Ctrl+C는 종료(→ Z)이고 Ctrl+Z는 멈춤(→ T)입니다. 시그널의 정식 규칙은 9주차에 다룹니다.

R: 실행 중과 실행 대기

R은 두 경우를 묶은 글자입니다. CPU에서 실제로 돌고 있는 중과 차례를 기다리는 중을 구분하지 않습니다. 그래서 R인 프로세스는 코어 수보다 많을 수 있고, 그렇다면 누군가는 실행 대기열에 줄을 서 있는 것입니다. 코어가 2개인 시스템에서 ps에 R이 5개 보인다면 2개는 CPU에서 실행 중이고 3개는 차례를 기다리는 중입니다.

S인 프로세스는 이 줄 밖에 있습니다. 잠든 프로세스는 CPU를 원하지 않으며, 기다리던 사건이 오면 그때 줄에 섭니다. 실습 서버는 48코어인데, 수백 개 프로세스 가운데 R은 보통 몇 개뿐입니다.

S와 D: 두 가지 잠

  • S: 깨울 수 있는 잠. sleep, 키보드 입력, 소켓·파이프 대기가 여기에 해당합니다. 시그널이 오면 깨어나 처리할 수 있습니다.
  • D: 깨울 수 없는 잠. 디스크나 네트워크 파일시스템 I/O 중에 짧게 들어갑니다. kill로도 깨지 않습니다.
  • 어디서 자는가. ps -o wchan은 프로세스가 잠든 커널 함수를 보여 줍니다. 예를 들면 hrtimer_nanosleep입니다.
ps -o pid,stat,wchan:20,command -p PID

state_show: 상태 관찰 대상 만들기

state_show는 스스로를 관찰 대상으로 만드는 프로그램입니다. 원하는 상태에 머무르는 프로세스를 만들어 놓고 다른 셸에서 그 상태를 봅니다.

for (long done = 1; done <= seconds; done++) {
    double next = start + (double)done;
    if (busy) {
        while (now_sec() < next) {
             /* R 관찰용: CPU를 놓지 않는다 */
        }
    } else {
        sleep(1);          /* S 관찰용: 1초씩 잠든다 */
    }
    printf("tick=%ld of %ld\n", done, seconds);
}
  • 두 모드: 기본은 잠자기(S)이고, --busy는 계산 루프(R)입니다.
  • 마감 시각: busy 루프는 CLOCK_MONOTONIC 기준으로 1초 마감까지 돕니다.
  • 관찰 안내: 시작할 때 비교할 ps 명령과 /proc 경로를 스스로 출력합니다.

실습 서버에서 S·R·T를 직접 만든 결과는 다음과 같았습니다.

  • S → T → S: 잠자는 프로세스를 SIGSTOP으로 멈추고 SIGCONT로 재개했습니다. Ctrl+Z와 fg로 일어나는 것과 같은 전이입니다. 셸은 멈춘 작업을 Stopped로 알립니다.
  • R과 %CPU: busy 모드는 R이고 %CPU가 100입니다.
  • 두 창 일치: ps의 STAT와 /proc의 State가 같은 글자를 보여 줍니다.

한 서버의 상태 분포

실습 서버에서 모든 프로세스의 상태 첫 글자를 세어 본 결과입니다.

ps -eo stat= | cut -c1 | sort | uniq -c

전체 928개 프로세스 가운데 S가 597개, I가 324개, R이 4개, Z가 3개였습니다(I는 커널 유휴 스레드).

  • 대부분은 잡니다. 서버 프로세스는 요청이 올 때까지 기다립니다.
  • R은 몇 개뿐입니다. 그중 하나는 이 명령을 실행한 ps 자신입니다. 48코어 중 대부분이 놀고 있다는 뜻입니다.
  • Z 3개는 회수되지 않은 좀비입니다. PPID로 부모를 찾아볼 수 있습니다.

좀비: 종료와 회수 사이

자식 프로세스의 일생을 시간 순으로 놓으면 실행(R·S) → exit → 좀비 Z(회수 대기) → 부모의 wait → 프로세스 표에서 사라짐입니다. exit하는 즉시 반납하는 것과 좀비가 남기는 것은 다음과 같이 나뉩니다.

  • exit 즉시 반납: 주소 공간(메모리), 열린 FD 전부, 작업 디렉터리 참조 등.
  • 좀비가 남기는 것: PID, 종료 상태(예: 7), CPU 시간 등 사용량 통계.

좀비는 모든 프로세스가 거치는 단계이고, 문제는 오래 남는 것입니다. 실습은 7주차 2차시의 reap_show에서 합니다.

잠자기와 좀비는 다르다

  • S: 살아 있습니다. 메모리와 FD를 그대로 들고 사건을 기다립니다. 깨어나면 일을 계속합니다.
  • Z: 이미 끝났습니다. 자원은 반납했고 종료 상태만 남았습니다. 어떤 시그널에도 반응하지 않습니다.
  • 구별법: STAT 첫 글자, ps의 <defunct> 표시, 그리고 status의 VmRSS 줄 유무입니다(좀비에는 없습니다).

한 줄로 줄이면, S는 사건이 깨우고 Z는 부모가 치웁니다.

FD 표, /proc/PID/status, 자원 한계를 관찰합니다.

FD 표의 세 층

3주차에 배운 FD를 오늘은 밖에서 관찰합니다. FD를 따라가면 세 층이 나옵니다.

  • FD 표 (프로세스별): 작은 정수에서 열린 파일 항목으로 가는 표입니다. open은 가장 작은 빈 번호를 줍니다.
  • 열린 파일 항목 (커널): 파일 위치(pos)와 열기 플래그를 담습니다. open 한 번에 하나가 생깁니다.
  • 아이노드: 실제 파일입니다. 여러 항목이 같은 파일을 가리킬 수 있습니다.

hold_open을 예로 들면, FD 0·1·2는 보통 같은 터미널(/dev/pts/0)을 가리키고, FD 3은 hold_open이 O_RDONLY로 연 Makefile(아이노드 2229069)을 위치 0에서 가리킵니다. dup과 fork로 항목을 공유하는 규칙은 10·12주차에 다시 만납니다.

hold_open: FD 관찰 대상 만들기

int fd = open(argv[1], O_RDONLY);
if (fd == -1) {
    perror(argv[1]);
    return 1;
}
printf("pid=%ld fd=%d path=%s\n",
       (long)getpid(), fd, argv[1]);
for (long done = 1; done <= seconds; done++) {
    sleep(1);                  /* 관찰할 시간 창 */
    printf("hold=%ld of %ld\n", done, seconds);
}
if (close(fd) == -1) {
    perror("close");
    return 1;
}
  • 번호 예측: 0·1·2가 열려 있으면 첫 open은 3을 돌려줍니다.
  • 시간 창: 열고 닫는 사이에 다른 셸에서 /proc/PID/fd를 봅니다.
  • close 검사: close도 실패할 수 있습니다. 결과를 확인하는 것이 원칙입니다.

/proc/PID/fd로 본 FD 표

/proc/PID/fd 디렉터리에는 FD 번호마다 심볼릭 링크가 하나씩 있고, 각 번호가 무엇을 가리키는지를 링크 대상으로 보여 줍니다. ls -l로 보았을 때 lr-x는 읽기 전용으로, l-wx는 쓰기 전용으로, lrwx는 읽기·쓰기로 연 FD입니다.

이 창으로 리다이렉션의 정체도 볼 수 있습니다. 리다이렉션은 셸이 프로그램을 실행하기 전에 FD 1·2를 파일로 바꿔 둔 것입니다. 프로그램은 이를 모릅니다. hold_open의 코드는 그대로이고, 번호가 가리키는 대상만 달라졌습니다.

fdinfo: 열린 파일 항목 엿보기

/proc/PID/fdinfo/번호는 FD 뒤에 있는 열린 파일 항목의 내용을 보여 줍니다. hold_open이 연 FD 3을 보면 다음과 같이 읽습니다.

  • pos: 다음 read가 시작할 파일 위치입니다. 아직 읽지 않아 0입니다.
  • flags (8진수): 0100000은 O_LARGEFILE입니다. 접근 모드 비트가 0이므로 O_RDONLY입니다. 플래그 값은 아키텍처마다 다를 수 있습니다.
  • ino: Makefile의 아이노드 번호입니다. ls -i Makefile의 결과(2229069)와 같습니다.

/proc/PID/status 읽기

status 파일은 다음 묶음으로 읽습니다. 형식은 커널 버전에 따라 줄이 늘어날 수 있습니다.

  1. 위 4줄 · 정체성과 상태: 실행 파일 이름(최대 15자), 상태 문자, PID와 부모 PID.
  2. FDSize: FD 표에 마련된 칸 수입니다. 열린 개수가 아닙니다.
  3. Vm으로 시작하는 7줄 · 메모리: 최고·현재 예약(VmPeak · VmSize), 상주(VmRSS), 구역별 크기(데이터 · 스택 · 코드 · 라이브러리).
  4. Threads: 스레드 수입니다. 1이면 단일 스레드입니다.
  5. 마지막 2줄 · 문맥 교환: 스스로 양보한 횟수와 빼앗긴 횟수입니다. 7주차 2차시에 측정합니다.

자원 한계: soft와 hard

자원 한계는 soft와 hard 한 쌍으로 주어집니다.

  • soft: 지금 적용되는 한계입니다. 넘으면 호출이 실패하거나 시그널이 옵니다.
  • hard: soft의 천장입니다. 일반 사용자는 soft ≤ hard 범위에서 soft를 올리고 내릴 수 있지만, hard는 낮출 수만 있고 되돌릴 수 없습니다. 다시 올리려면 권한이 필요합니다.
  • 상속: 한계는 자식에게 그대로 물려집니다. 셸의 ulimit가 그 예입니다.

실습 서버에서 procdump가 출력한 RLIMIT_NOFILE의 실제 값은 soft 1024, hard 1048576이었습니다. 현재 열린 FD가 4개인 프로세스가 FD를 계속 열어 soft 한계에 닿으면, 그 지점의 open은 EMFILE로 실패합니다.

3부 코드 읽기 · hold_open과 procdump

hold_open.c

hold_open은 파일을 열어 둔 채 FD 표를 관찰하게 하는 프로그램입니다. 전역 변수는 없고 변수는 모두 main의 지역입니다. 눈여겨볼 것은 fd 변수의 수명과 열린 파일 항목의 수명이 다르다는 점입니다.

  • 파일 주석. open은 남은 가장 작은 번호를 돌려주므로 표준 스트림(0·1·2)만 열려 있으면 3이 돌아온다는 번호 규칙과, 실패 경로에서도 연 FD는 닫는다는 3주차 이후의 반복 원칙을 적어 두었습니다.
  • 인자. FILE은 필수이고 초는 선택입니다(기본 10, 1–600). 잘못된 인자는 사용법과 종료 2입니다.
  • int fd = open(argv[1], O_RDONLY); 번호 자체는 지역 변수의 값이지만, 그 번호가 가리키는 열린 파일 항목은 커널 안의 자료구조이며 변수가 아닙니다. 이 항목은 close하거나 프로세스가 끝날 때까지 남습니다. 변수의 수명과 자원의 수명이 다릅니다. 열기에 실패하면 파일 이름으로 perror하고 종료 1입니다.
  • 실패 경로에서도 반납. PID·fd·경로와 두 관찰 명령(ls -l /proc/PID/fd, ls /proc/PID/fd | wc -l)을 출력한 뒤 flush하는데, flush가 실패해도 close(fd)를 하고 나갑니다. 1초마다 진행을 출력하는 대기 루프 안에서도 같습니다.
  • close와 마무리. close도 실패할 수 있어 결과를 검사합니다. close 뒤에도 변수 fd는 남아 있지만 항목은 이미 반납된 상태입니다. 닫은 번호를 closed fd=…로 출력하고 flush한 뒤 종료 0입니다.

  • /proc가 없을 때. /proc/self/status를 열지 못하면 Linux에서는 perror와 종료 1이고, 다른 시스템에서는 proc_status=unavailable (no /proc)을 출력하고 계속 진행합니다. /proc/self/fd도 같은 방식으로 fd_count=unavailable (no /proc)을 출력합니다.

    char *colon = strchr(line, ':');
*colon = '\0';
char *value = colon + 1;
  • 오류 모으기와 두 failed. 첫째 failed는 ferror(fp)의 결과를 담고, fclose 실패도 여기에 모아 한 번에 종료 1로 나갑니다. 이 변수는 else 블록이 끝나면서 사라집니다. FD를 세는 블록에 나오는 int failed = errno != 0;은 이름만 같은 다른 변수입니다. 다른 블록이고, 앞의 failed는 이미 사라진 뒤입니다.
  • FD 세기. readdir를 부르기 전에 errno를 0으로 두고, .으로 시작하는 항목(.·..)을 빼고 셉니다. 루프가 끝난 뒤 errno가 0이 아니면 readdir 오류로 봅니다. 소스의 주석대로 스캔 자체가 FD 하나를 쓰므로 Linux에서는 표준 3개보다 하나 더 세는 것이 정상이고, 그래서 결과를 fd_count=… includes_scan_fd=yes로 출력합니다. 관찰도 증거에 영향을 준다는 뜻입니다. 끝으로 closedir와 fflush를 검사하고 종료 0입니다.

코드 읽기 정리

  • 전역: 함수 밖 선언입니다. 1차시에서는 addr_show의 global_init·global_zero 둘뿐입니다.
  • 지역: 함수·블록 안 선언입니다. 매개변수도 지역입니다. 블록이 끝나면 사라지고, 같은 이름을 다른 블록에서 다시 쓸 수 있습니다.
  • static 지역: 선언 위치는 함수 안이지만 수명과 구역은 전역과 같습니다. 함수 앞의 static은 다른 뜻(이 파일 안에서만)입니다.
  • 힙: 변수가 아니라 블록입니다. 지역 포인터가 가리키며, free할 때까지 남습니다.

다음 차시의 fork·exec에서는 "지역 변수가 두 프로세스에 복제된다"는 사실을 다시 만납니다.

판단은 표준 API로 하고, 설명과 진단은 /proc와 ps로 합니다.

이것으로 할 수 있는 일

  • 멈춘 프로그램 진단: STAT이 R이면 계산 루프를, S면 무엇을 기다리는지 wchan을 보고, D가 길면 저장 장치를 의심합니다.
  • 메모리 누수 의심: VmRSS를 시간 간격으로 기록해 계속 늘기만 하는지 봅니다. VmSize만 큰 것은 문제가 아닙니다.
  • FD 누수 찾기: ls /proc/PID/fd | wc -l이 계속 늘면 close가 빠진 것입니다. 한계에 닿으면 EMFILE입니다.
  • 좀비 원인 찾기: Z의 PPID로 부모를 찾습니다. 고칠 것은 자식이 아니라 부모의 회수(wait) 코드입니다.
  • 리다이렉션 · 로그 확인: 서비스의 FD 1·2가 어디로 가는지 /proc/PID/fd로 보면 로그 파일 위치를 알 수 있습니다.
  • 서비스 한계 점검: /proc/PID/limits로 실행 중인 서버의 NOFILE 한계를 확인하고 동시 연결 수와 비교합니다.

관찰이 먼저이고, 수정은 그다음입니다.

정리

  • 주소 공간: 저장 기간이 구역을 정하고, maps 한 행은 범위·권한·파일을 말합니다.
  • 메모리 숫자: VmSize는 예약, VmRSS는 지금 올라와 있는 양입니다.
  • 상태: R은 실행·대기, S·D는 잠, T는 멈춤, Z는 회수를 기다리는 종료입니다.
  • 자원: FD는 열린 파일 항목을 가리키는 번호이고, 한계는 soft·hard 한 쌍입니다.
  • 확인: 프로그램의 보고를 ps · /proc/PID와 교차 검증합니다.
