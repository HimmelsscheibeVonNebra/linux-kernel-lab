Linux Lab/3주차 2차시 · text-binary

텍스트와 바이너리 파일 입출력 실습

텍스트 예제로 FD 함수(open/read/write/lseek)를 복습하고, int 3개짜리 바이너리 파일로 FILE* 함수(fopen/fread/fwrite/fseek)를 익힌다.

실행해 볼 예제

  • file_writeopen에 O_TRUNC 또는 O_APPEND를 주고 write_all로 TEXT 바이트를 그대로 기록한다. 덮어쓰기와 추가, 그리고 쓰기 오류 처리를 확인한다.
  • file_read16바이트 버퍼로 EOF(read가 0 반환)까지 반복해서 읽고 읽은 만큼만 표준 출력에 쓴다. 텍스트든 바이너리든 바이트 그대로 전달한다.
  • file_seeklseek로 바이트 위치를 옮겨 수정 전 내용을 읽어 보여 주고, 같은 위치로 다시 이동해 TEXT를 덮어쓴다.
  • binary_writefopen("wb")으로 열어 int 배열 {10, 20, 30}을 fwrite로 헤더 없이 그대로 저장한다.
  • binary_readfopen("rb")과 fread로 int 3개를 읽어 십진수로 출력한다. 항목이 부족하거나 뒤에 데이터가 더 있으면 오류로 처리한다.
  • binary_seekfseek로 INDEX * sizeof(int) 위치로 이동해 항목 하나를 fread로 읽거나, r+b 모드에서 fwrite로 그 항목만 수정한다.
  • test_write_allwrite를 가짜 함수(scripted_write)로 바꿔 부분 쓰기, EINTR, 0 반환, ENOSPC 등의 상황을 재현하고 io_helpers.h의 write_all이 올바르게 처리하는지 assert로 검사한다.

이번 수업은 두 부분으로 나뉩니다. 1부에서는 read, write, lseek로 텍스트를 저장하고 읽는 과정을 복습하고, 2부에서는 fread, fwrite, fseek로 정수 배열을 바이너리로 저장하고 읽는 방법을 새로 배웁니다.

먼저 한 가지를 분명히 해 둡니다. 학습 순서 때문에 텍스트는 파일 디스크립터(FD) 함수군으로, 바이너리는 FILE* 함수군으로 설명하지만, read/write가 텍스트 전용이고 fread/fwrite가 바이너리 전용이라는 뜻은 아닙니다. 두 함수군 모두 텍스트와 바이너리를 처리할 수 있습니다. 두 함수군의 실제 차이는 FD와 스트림이라는 파일 표현, 처리 단위(바이트와 항목), 그리고 라이브러리 버퍼링에 있습니다. 따라서 "예제가 어떤 형식으로 저장하는가"와 "어떤 API를 쓰는가"는 서로 다른 문제로 구분해서 보아야 합니다.

1부 · 복습: 텍스트 저장과 읽기

1부에서는 read(), write(), lseek()로 파일에 들어 있는 바이트와 파일 위치를 확인합니다. 대응하는 예제는 file_write, file_read, file_seek입니다.

텍스트 파일의 바이트

예제에서 사용하는 데이터는 ASCII 문자열 ABCDEFGHIJ입니다. 파일에는 이 문자 10개에 해당하는 10바이트가 저장됩니다. C에서 문자열 리터럴 끝에는 NUL 문자가 붙어 있지만, 이번 예제에서는 그 NUL을 파일에 쓰지 않습니다.

텍스트도 결국 바이트의 나열입니다. 예를 들어 ASCII 문자 A는 0x41이라는 한 바이트입니다. UTF-8로 인코딩한 한글은 한 문자가 한 바이트에 대응하지 않기 때문에, 위치를 바이트 단위로 따져 보는 이번 예제에서는 ASCII만 사용합니다.

파일 위치는 다음에 읽거나 쓸 바이트의 위치를 뜻합니다. 읽거나 쓰면 그만큼 위치가 앞으로 나아가며, 1부의 예제는 모두 이 위치가 어떻게 움직이는지를 관찰하는 내용입니다.

open과 close 복습

open은 성공하면 0 이상의 파일 디스크립터를 반환하고, 실패하면 -1을 반환합니다. 플래그 가운데 O_RDWR은 읽기와 쓰기를 모두 허용하고, O_TRUNC는 기존 파일의 내용을 지웁니다. 사용이 끝난 FD는 close로 닫습니다.

int fd = open("text.txt",
    O_RDWR | O_CREAT | O_TRUNC, 0644);
if (fd == -1) {
    perror("open");
    return 1;
}
/* write, read, lseek 실행 */
if (close(fd) == -1) return 1;

위 코드는 main의 흐름만 발췌한 것으로, 헤더는 fcntl.h, unistd.h, stdio.h를 사용합니다. 여기서는 정상 경로만 보이지만, 중간에 실패해서 빠져나가는 모든 경로에서도 close가 필요합니다.

write · 텍스트 저장

write는 buf가 가리키는 메모리에서 count바이트를 파일에 씁니다. 반환값은 실제로 쓴 바이트 수이며, 성공하면 0 이상, 오류이면 -1입니다.

ssize_t write(int fd, const void *buf,
              size_t count);

const char text[] = "ABCDEFGHIJ";
ssize_t n = write(fd, text, sizeof text - 1);
/* 요청은 10바이트 */
/* 성공: 0 이상, 오류: -1 */

sizeof text는 끝의 NUL까지 포함한 11이므로, 1을 빼서 문자 10개만 쓰도록 요청합니다.

중요한 점은 반환값이 요청한 크기보다 작을 수 있다는 것입니다. 이를 부분 쓰기라고 하며, 이 경우 남은 바이트를 다시 써야 합니다. 예를 들어 write가 4를 반환했다면 4바이트만 처리된 것이므로, 다음 요청은 text+4에서 시작하는 6바이트가 됩니다. 또한 -1과 함께 EINTR이 보고되면 다시 시도하고, 그 밖의 오류와 진행 없이 0을 반환하는 경우도 처리해야 합니다. 완성된 실습 코드에서는 이 과정을 맡아 주는 write_all 함수가 제공되며, test_write_all이 부분 쓰기, EINTR, 진행 없는 0 반환, 쓰기 오류 상황을 재현해 이 함수를 검사합니다.

read · 텍스트 읽기

read는 최대 count바이트를 읽어 버퍼에 저장합니다. 반환값이 양수이면 실제로 읽은 길이이고, 0이면 파일의 끝(EOF)이며, -1이면 오류입니다.

char buf[16];
ssize_t n = read(fd, buf, sizeof buf - 1);
if (n == -1) {
    /* 오류 처리 */
} else {
    buf[n] = '\0';
    printf("%s", buf);
}

read는 읽은 데이터 뒤에 NUL을 자동으로 붙여 주지 않습니다. 그래서 읽은 내용을 C 문자열로 다루려면 버퍼에 NUL이 들어갈 한 칸을 남겨 두고(sizeof buf - 1), 읽은 길이 n 위치에 직접 '\0'을 넣어야 합니다.

또 하나 주의할 점은 파일 위치입니다. 같은 FD로 방금 write를 했다면 현재 위치는 파일 끝에 가 있으므로, 읽기 전에 lseek로 위치를 되돌려야 합니다. 위 예제는 일반 파일을 한 번 읽는 경우이며, EOF까지 모두 처리하려면 read를 반복해서 호출합니다.

lseek · 읽기와 쓰기 위치

lseek는 파일 위치를 옮깁니다. offset은 기준점(whence)에서 이동할 바이트 수입니다. 성공하면 새 파일 위치를 반환하고, 실패하면 (off_t)-1을 반환합니다.

off_t lseek(int fd, off_t offset, int whence);

lseek(fd, 0, SEEK_SET); /* 파일 시작 */
lseek(fd, 3, SEEK_SET); /* 시작에서 3 */
lseek(fd, -2, SEEK_CUR); /* 현재에서 -2 */
lseek(fd, 0, SEEK_END); /* 파일 끝 */

위의 네 호출은 각각 독립적인 위치 지정 예시이며, 실제 코드에서는 반환값을 검사합니다. lseek 자체는 데이터를 읽거나 쓰지 않고 위치만 바꿉니다. 파일 위치는 바이트 단위입니다. 파이프 같은 대상에서는 lseek를 사용할 수 없고, 파일을 O_APPEND로 열었다면 위치를 어디로 옮기든 각 write는 파일 끝에 기록됩니다.

텍스트 위치 예제

파일 내용이 ABCDEFGHIJ이고 O_RDWR로 열려 있다고 합시다. 시작에서 3바이트 이동하면 위치 0, 1, 2의 A, B, C를 지나 D의 위치가 됩니다. 여기서 2바이트를 읽으면 DE를 얻고, 다음 위치는 5가 됩니다. 다시 위치 3으로 이동해 XY를 쓰면 그 자리의 두 바이트가 바뀝니다.

/* text.txt: ABCDEFGHIJ, O_RDWR */
lseek(fd, 3, SEEK_SET);
read(fd, buf, 2);
/* 읽은 데이터: DE */

lseek(fd, 3, SEEK_SET);
write(fd, "XY", 2);
/* 파일 결과: ABCXYFGHIJ */

결과가 ABCXYFGHIJ인 것에서 알 수 있듯이, 파일 중간에 쓰는 것은 덮어쓰기입니다. 기존 데이터를 뒤로 밀어 넣으면서 끼워 넣는 것이 아니므로 파일 길이는 그대로 10바이트입니다. 이 코드는 위치의 흐름을 보여 주는 발췌로, 각 호출이 성공하고 요청한 바이트를 모두 처리했다고 가정합니다. 실제 코드는 반환값을 검사하고 부분 읽기와 부분 쓰기를 처리합니다.

1부 확인: 반환값과 버퍼

1부에서 기억할 것은 반환값과 버퍼의 경계입니다.

  • write가 4를 반환했다면 4바이트만 처리된 것입니다. 나머지는 아직 쓰이지 않았습니다.
  • read가 2를 반환했다면 버퍼에서 유효한 것은 읽은 2바이트뿐이므로 그 2바이트만 사용합니다. 다만 요청보다 짧은 양수가 반환되었다는 사실만으로 EOF라고 단정해서는 안 됩니다. EOF는 반환값 0으로 확인합니다.
  • char buf[4]의 유효 인덱스는 0부터 3까지입니다. 텍스트 ABCD를 C 문자열로 담으려면 NUL까지 5바이트가 필요하므로 이 버퍼로는 부족합니다.
  • 버퍼 끝 밖에 쓰는 것을 overflow, 버퍼 시작 앞에 쓰는 것을 underwrite라고 합니다. 메모리 경계 밖을 읽거나 쓰는 것은 정의되지 않은 동작입니다.
  • 이름이 비슷한 underflow는 다른 개념입니다. 스트리밍에서 소비할 데이터가 부족한 상황을 가리키며, 메모리 경계를 벗어나 쓰는 underwrite와 구별해야 합니다.

2부 · 바이너리 저장과 읽기

2부에서는 fread(), fwrite(), fseek()로 정수 배열을 저장하고 읽습니다. 대응하는 예제는 binary_write, binary_read, binary_seek입니다.

텍스트 표현과 바이너리 표현

같은 숫자 1234도 두 가지 방식으로 파일에 저장할 수 있습니다.

  • 텍스트: 숫자 1234를 문자 "1234"로 저장합니다. ASCII로는 줄바꿈 없이 4바이트입니다. 다시 숫자로 쓰려면 문자를 해석해 숫자로 변환하는 과정이 필요합니다.
  • 바이너리: 정수 값이 메모리에 놓여 있는 바이트를 그대로 저장합니다. 크기는 sizeof(int)로 확인합니다. 변환은 필요 없지만, 읽는 쪽이 자료형과 저장 형식을 알고 있어야 합니다.

바이너리가 항상 더 작다는 뜻은 아닙니다. 또한 메모리 내용을 그대로 저장하는 방식은 int의 크기, 엔디언(바이트 순서), 구조체 패딩이 환경마다 다를 수 있기 때문에, 서로 다른 환경 사이에서 주고받는 교환 형식으로는 적절하지 않을 수 있습니다. 이번 예제는 같은 환경에서 int 배열을 쓰고 읽는 경우만 다룹니다.

FILE*와 fopen

FILE*는 C 라이브러리가 제공하는 스트림입니다. 정수인 FD와 달리 라이브러리가 관리하는 객체를 가리키는 포인터이며, fopen으로 얻습니다. 실패하면 NULL을 반환하므로 이를 확인합니다.

FILE *fp = fopen("numbers.bin", "wb");
if (fp == NULL) {
    perror("fopen");
    return 1;
}
/* fwrite로 저장 */
if (fclose(fp) == EOF) return 1;

두 번째 인자인 모드 문자열이 열기 방식을 정합니다.

  • wb: 새로 쓰기 모드입니다. 기존 파일 내용을 지웁니다.
  • rb: 기존 파일을 읽는 모드입니다.
  • r+b: 기존 파일의 읽기와 쓰기를 모두 허용합니다. 기존 내용은 보존됩니다.

Linux에서는 b가 동작을 바꾸지 않습니다. 그래도 바이너리 모드를 구분하는 다른 환경을 위해 명시해 둡니다. 헤더는 stdio.h입니다.

fwrite · 바이너리 저장

fwrite(ptr, size, nmemb, stream)은 메모리의 바이트를 스트림에 기록합니다. size는 항목 하나의 크기, nmemb는 저장할 항목 개수이며, 반환값은 성공적으로 쓴 항목 수입니다. 반환형은 size_t입니다.

/* fwrite(ptr, size, nmemb, stream) */
int values[] = {10, 20, 30};

size_t n = fwrite(values,
                 sizeof values[0], 3, fp);
if (n != 3) {
    /* 쓰기 오류 처리 */
}
/* 요청 크기: 3 * sizeof(int) */

write가 바이트 수를 돌려주는 것과 달리 fwrite는 항목 수를 돌려주므로, 성공 여부는 요청한 개수 3과 비교해서 판단합니다. 요청보다 적은 항목 수가 반환되면 쓰기 오류로 처리합니다. 그리고 fwrite가 성공했다고 끝이 아닙니다. 뒤에서 설명하듯 데이터가 라이브러리 버퍼에 남아 있을 수 있어서, fclose가 버퍼를 내보내는 과정에서 실패할 수도 있습니다.

fread · 바이너리 읽기

읽을 때는 저장할 때와 같은 항목 크기와 개수를 사용합니다. fread(ptr, size, nmemb, stream)은 읽은 결과를 ptr이 가리키는 곳에 저장하고, 완전히 읽은 항목 수를 반환합니다.

/* fp: numbers.bin을 rb로 연 스트림 */
int values[3];
size_t n = fread(values,
                 sizeof values[0], 3, fp);
if (n != 3) {
    if (ferror(fp)) { /* 읽기 오류 */ }
    else { /* 파일 내용이 부족함 */ }
}
/* n == 3일 때 값: 10, 20, 30 */

n이 3이면 int 3개를 완전히 읽은 것입니다. 3보다 작다면 두 가지 경우가 있으므로 구별해야 합니다. ferror(fp)가 참이면 읽기 오류이고, 그렇지 않으면 파일 내용이 부족해 EOF에 도달한 것입니다.

반환 개수에는 완전히 읽은 항목만 포함됩니다. 파일 끝에 int 하나를 채우지 못하는 바이트만 남아 있었다면 그 불완전한 마지막 항목은 개수에 들어가지 않으며, 이를 유효한 int 값으로 사용해서는 안 됩니다.

항목 수와 바이트 수

fread와 fwrite의 단위는 size 인자에 따라 달라집니다.

  • fread(values, sizeof(int), 3, fp)의 단위는 int입니다. 반환값은 읽은 int의 개수입니다.
  • fread(buf, 1, sizeof buf, fp)의 단위는 바이트입니다. size가 1이므로 반환값이 곧 읽은 바이트 수입니다.

어느 경우든 실제로 요청하는 바이트 수는 size × nmemb입니다. 예를 들어 sizeof(int)가 4인 환경에서 세 항목을 모두 읽으면 전송량은 12바이트이고 반환값은 3입니다. 버퍼에는 요청 전체를 담을 공간이 있어야 하고, 이 곱셈이 오버플로하지 않는지도 주의해야 합니다. fwrite에서도 마찬가지로, 버퍼 크기보다 많이 요청하면 범위 밖의 메모리를 읽게 됩니다.

read와 마찬가지로 fread도 문자열 끝의 NUL을 붙여 주지 않습니다.

fseek · 바이너리 파일 위치

fseek는 스트림의 파일 위치를 옮깁니다. 기준점으로는 lseek와 같은 SEEK_SET, SEEK_CUR, SEEK_END를 사용합니다. 주의할 점은 offset이 항목 개수가 아니라 바이트 수라는 것입니다. fread/fwrite가 항목 단위로 동작하더라도 위치는 여전히 바이트로 지정합니다.

int fseek(FILE *stream, long offset,
          int whence);

/* 두 번째 int: 인덱스 1 */
long offset = (long)sizeof(int);
if (fseek(fp, offset, SEEK_SET) != 0) {
    /* 위치 이동 오류 처리 */
}

반환값도 lseek와 다릅니다. lseek는 새 위치를 반환하지만 fseek는 성공하면 0, 실패하면 0이 아닌 값을 반환할 뿐 새 위치를 알려 주지 않습니다. 현재 위치가 필요하면 ftell(fp)를 호출하고, 그 반환값이 오류를 뜻하는 -1L인지 확인합니다. 성공한 fseek는 스트림의 EOF 표시를 해제합니다. 이 설명은 Linux의 일반 바이너리 파일을 기준으로 한 것이며, 대용량 파일에서는 off_t를 쓰는 fseeko/ftello도 고려합니다.

원하는 항목 하나 읽기

같은 크기의 항목이 연속으로 저장된 파일에서는 인덱스 k인 항목의 위치가 k × 항목 크기입니다. 인덱스는 0부터 시작하므로, 두 번째 값 20은 인덱스 1이고 시작 위치는 sizeof(int)바이트입니다. sizeof(int)가 4인 환경이라면 4바이트 위치입니다.

/* fp: numbers.bin을 rb로 연 스트림 */
int value;
long offset = (long)sizeof value;
if (fseek(fp, offset, SEEK_SET) != 0)
    goto fail;
if (fread(&value, sizeof value, 1, fp) != 1)
    goto fail;
printf("%d\n", value); /* 20 */

항목 하나를 요청했으므로 fread의 반환값이 1인지 확인한 뒤에만 value를 사용합니다. fail 레이블은 fclose로 스트림을 닫고 실패 상태를 반환하는 오류 처리 경로입니다.

원하는 항목 하나 수정

파일의 일부만 고치려면 기존 내용을 보존해야 하므로 r+b 모드로 엽니다. wb로 열면 내용이 모두 지워지므로 이 용도에는 쓸 수 없습니다. 두 번째 int 위치로 이동해 99를 쓰면, 텍스트 예제의 덮어쓰기와 마찬가지로 그 항목만 바뀌어 배열은 10, 99, 30이 됩니다.

FILE *fp = fopen("numbers.bin", "r+b");
if (!fp) return 1;
int value = 99;
if (fseek(fp, (long)sizeof value, SEEK_SET) != 0)
    goto fail;
if (fwrite(&value, sizeof value, 1, fp) != 1)
    goto fail;
if (fclose(fp) == EOF) return 1;

여기서도 fail 레이블은 스트림을 닫고 실패를 반환하는 공통 경로이며, 성공하면 main이 0을 반환하도록 구성합니다. 이 예제는 파일에 헤더가 없고 int가 연속으로 저장되어 있다고 가정합니다.

읽기와 쓰기 전환

r+b처럼 읽기와 쓰기가 모두 가능한 스트림에서 같은 FILE*로 읽기와 쓰기를 오갈 때는 지켜야 할 전환 규칙이 있습니다.

  • 쓰기 후 읽기: 그 사이에 fflush 또는 위치 지정 호출이 필요합니다.
  • 읽기 후 쓰기: 보통 그 사이에 위치 지정 호출이 필요합니다. 앞선 읽기가 EOF를 만난 경우는 예외입니다.

이 수업에서는 전환할 때마다 fseek로 다음 위치를 지정하는 방식을 씁니다. 0바이트 이동이라도 fseek는 위치 지정 호출의 역할을 합니다. fseek가 성공했는지 확인한 뒤에 다음 작업을 진행합니다.

이런 규칙이 있는 이유는 스트림이 라이브러리 버퍼와 자체 위치를 가지고 있기 때문입니다. 같은 이유로, 한 파일에 FD 함수와 stdio 함수를 무분별하게 섞어 쓰지 않습니다.

버퍼링과 파일 닫기

stdio는 라이브러리 버퍼에 입출력을 모아서 처리할 수 있습니다. 그래서 fwrite가 성공을 반환한 뒤에도 데이터가 아직 출력 버퍼에 남아 있을 수 있습니다.

  • fflush는 출력 버퍼의 데이터를 커널로 내보냅니다.
  • fclose는 출력 버퍼를 처리한 뒤 파일을 닫습니다.

두 함수 모두 성공하면 0, 실패하면 EOF를 반환하므로 반환값을 검사해야 합니다. 버퍼에 남아 있던 데이터를 내보내다 실패할 수 있기 때문에, fclose의 결과까지 확인해야 쓰기가 끝났다고 말할 수 있습니다.

fflush는 데이터를 커널까지 보낼 뿐, 디스크에 영구 저장되었음을 보장하지는 않습니다. 지속성이 요구되는 경우에는 fflush가 성공한 뒤 fsync(fileno(fp)) 등을 별도로 고려합니다. 입력 쪽에서는 버퍼가 비면 라이브러리가 다시 채울 수 있으며, 버퍼가 비었다는 것 자체가 EOF를 뜻하지는 않습니다.

실습: 저장, 선택 읽기, 수정

2부의 내용을 다음 순서로 직접 확인합니다.

  1. int 배열 {10, 20, 30}을 fwrite로 저장합니다.
  2. rb로 열고 fread로 전체 배열을 확인합니다.
  3. fseek로 두 번째 항목을 읽어 20인지 확인합니다.
  4. r+b로 열어 두 번째 항목을 99로 바꿉니다.
  5. 다시 읽어 {10, 99, 30}인지 확인합니다.

각 fopen, fread, fwrite, fseek, fclose의 반환값을 모두 검사합니다. 빈 파일이나 일부 바이트만 들어 있는 파일에서는 완전한 세 항목 읽기가 실패해야 정상입니다. 그리고 저장된 것은 int의 원시 바이트이므로, 텍스트 편집기로 열었을 때 숫자가 읽힐 것으로 기대해서는 안 됩니다.

정리 퀴즈

  1. write에 정수의 주소를 전달하면 무엇을 저장합니까? count로 지정한 만큼의 메모리 바이트를 저장합니다. 자동으로 숫자 문자열로 바꿔 주지 않습니다.
  2. int 3개를 쓴 fwrite의 성공 반환값은 무엇입니까? size가 sizeof(int)이고 nmemb가 3이면 3입니다.
  3. 세 번째 int의 시작 위치는 몇 바이트입니까? 2 * sizeof(int)입니다.
  4. fseek가 성공했을 때의 반환값과 현재 위치는 같습니까? 다릅니다. fseek의 성공 반환값은 0이며, 현재 위치는 ftell로 확인합니다.
