프로세스 생성과 실행: fork · exec · wait

fork로 프로세스를 만들고 exec로 프로그램을 교체하며 wait·waitpid로 종료 상태를 회수하는 흐름과 atexit·stdio 버퍼의 동작을 다룬다.

  • forkfork가 한 번 호출되어 부모(자식 PID 반환)와 자식(0 반환)에서 두 번 반환되는 것을 getpid·getppid 출력으로 확인한다.
  • execlpexeclp가 PATH에서 ls를 찾아 현재 프로세스를 교체하므로 성공하면 exec 뒤의 코드는 실행되지 않고, 실패할 때만 -1로 돌아옴을 보여 준다.
  • execvexecv에 실행 파일 경로(/bin/ls)와 인자 배열을 직접 넘겨 프로세스를 교체한다. PATH 탐색이 없다는 점이 execlp와 다르다.
  • forkNexecfork한 자식에서 execlp로 ls를 실행하는, 셸이 명령을 실행하는 방식(fork + exec)을 보여 준다. 부모는 기다리지 않고 끝난다.
  • wait자식이 exit(2)로 끝나면 부모가 wait로 회수해 status(512 = 0x200)와 WEXITSTATUS(2)를 출력한다.
  • waitpid자식이 3초 자는 동안 부모가 waitpid(WNOHANG)로 1초마다 찔러 보고(0 반환), 자식이 끝나면 종료 코드 3을 회수한다.
  • atexitatexit로 등록한 정리 함수가 exit 호출 시 등록의 역순으로 실행됨을 보여 준다.
