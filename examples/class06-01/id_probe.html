id_probe

getpid·getppid·getpgrp·getsid로 프로세스 정체성을 출력하고 ttyname으로 표준 입력에 연결된 터미널을 확인합니다.

준비 중…

/home/student/class06-01에서 student 사용자로 시작합니다. 컴파일된 실행 파일과 소스가 이미 들어 있습니다. 새로고침하거나 재부팅하면 처음 상태로 돌아갑니다.

실행 순서

  1. ./id_probe

    pid, ppid(셸의 PID), pgid, sid와 tty 이름을 확인합니다.

  2. ./id_probe < /dev/null

    표준 입력이 터미널이 아니면 ttyname이 NULL이라 tty=(none)이 됩니다.

  3. ./id_probe | cat

    출력만 파이프로 보내면 표준 입력은 여전히 터미널이라 tty가 그대로입니다.

  4. ps -o pid,ppid,pgid,sid,tty,stat,args | grep -E "PID|^ *$$ "

    셸 자신($$)의 줄입니다. id_probe의 ppid·sid와 맞춰 봅니다.

  5. sleep 30 & ps -o pid,ppid,pgid,sid,args | grep -E 'PID|[s]leep 30'; kill $!

    백그라운드 작업의 PPID는 셸의 PID이고, 작업 제어가 켜진 셸에서는 PGID가 자기 PID입니다.

프로그램이 마지막에 안내하는 'ps ... -p PID' 형식은 BusyBox ps가 지원하지 않습니다(-p 옵션과 command 열 없음). 대신 ps -o ... | grep 으로 확인합니다.

소스

id_probe.c 33줄 
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
 
/* 오늘의 정체성 조회 네 개는 모두 인자 없이 pid_t를 돌려주고
   실패 경로를 정의하지 않는다. pid_t의 크기는 시스템마다 다를
   수 있으므로 출력 전에 (long)으로 변환한다. */
int main(int argc, char **argv)
{
    if (argc != 1) {
        fprintf(stderr, "usage: %s\n", argv[0]);
        return 2;
    }
    printf("pid=%ld\n", (long)getpid());
    printf("ppid=%ld\n", (long)getppid());
    printf("pgid=%ld\n", (long)getpgrp());
    printf("sid=%ld\n", (long)getsid(0));
    /* 표준 입력이 터미널이 아니면(입력 리다이렉션·크론 등)
       ttyname이 NULL을 돌려준다. 이것도 관찰 결과다. */
    const char *tty = ttyname(STDIN_FILENO);
    if (tty == NULL) {
        printf("tty=(none)\n");
    } else {
        printf("tty=%s\n", tty);
    }
    printf("compare: ps -o pid,ppid,pgid,tty,stat,command -p %ld\n",
           (long)getpid());
    if (fflush(stdout) == EOF) {
        perror("stdout");
        return 1;
    }
    return 0;
}
